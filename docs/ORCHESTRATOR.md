# ◆ Оркестратор Umnik

◆ Оркестратор - специальный защищённый чат проекта. Он нужен не для отдельной роли вроде «Автор» или «Аналитик», а для управления остальными участниками проекта.

## Основная идея

Пользователь формулирует задачу обычным разговорным языком, а Оркестратор превращает её в ограниченный план действий внутри проекта.

Пример:

> Пусть Исследователь с поиском найдёт пять вариантов. Потом Проверяющий отсеет слабые, а Автор подготовит итоговый текст.

Вместо ручного перехода между чатами Umnik выполняет нужные целевые чаты в фоне. Независимые исполнители могут работать параллельно; если шаг использует результат предыдущего, зависимая часть остаётся последовательной. Каждый исполнитель использует собственный рабочий профиль: модель, reasoning, веб-поиск, OpenRouter tools, навыки, роль, инструкции, постоянные файлы, базу знаний и историю.

## Что Оркестратор умеет

В текущей версии он может:

- выполнить выбранный чат с новым промптом;
- выполнить индивидуальные этапы выбранного чата;
- выполнить общие этапы проекта;
- передать результат предыдущего шага следующему;
- показать последний результат выбранного чата без нового запроса к модели;
- использовать последний результат как материал для доработки;
- передать файлы между чатами проекта;
- временно переопределить модель, веб-поиск, reasoning, силу reasoning и набор навыков на один запуск;
- изменить постоянные настройки чата только по явной команде пользователя;
- запускать сохранённый ручной сценарий Оркестратора;
- параллельно запускать независимых исполнителей без фиксированного размера группы.

Разговорный план ограничен восемью действиями за один запуск. Это сделано намеренно: текущая цель Umnik - предсказуемая и контролируемая многоходовая работа.

## Что происходит с историей

Когда Оркестратор реально выполняет другой чат, задача добавляется в историю целевого чата как пользовательское сообщение, а результат модели - как ответ ассистента.

Поэтому после цепочки:

**Исследователь → Проверяющий → Автор**

каждый чат сохраняет собственную историю работы. Оркестратор дополнительно ведёт журнал выполнения у себя.

Это важное отличие от простого «склеивания промптов»: целевые чаты остаются самостоятельными рабочими специалистами.

## Доработки без повторного запуска всей цепочки

После результата можно дать новую человеческую команду:

> Верни последний текст Автору и попроси убрать длинное вступление, но сохранить все факты.

Или:

> Покажи, что получилось у Проверяющего.

Или:

> Передай замечания Редактора Автору и попроси исправить только отмеченные места.

Так пользователь может вмешиваться между ходами и дорабатывать только нужную часть проекта.

## Временные настройки

Полезный сценарий - изменить поведение исполнителя только для одного задания.

Например:

> На этот запуск включи Исследователю веб-поиск и высокий reasoning, потом вернись к его обычным настройкам.

Постоянный профиль чата при таком запуске не обязан меняться. Это позволяет держать экономичную конфигурацию по умолчанию и усиливать конкретный шаг только при необходимости.

## Файлы

Оркестратор может передавать доступные файлы между чатами проекта.

Например:

> Файл, который сделал Аналитик, передай Автору и попроси подготовить итоговый материал.

Передача файла и передача текстового результата - разные механизмы. Файл может быть использован разово либо закреплён в целевом чате, если действие явно этого требует.

## Базы знаний исполнителей

Если у целевого чата настроена база знаний, она продолжает работать и при запуске через Оркестратор.

Например, у чата «Дизайнер» может быть своя библиотека по UX/UI, а у «Редактора» - отдельные справочники по редактуре. При запуске каждого исполнителя Umnik выполняет семантический поиск именно по доступной ему базе знаний и добавляет релевантные фрагменты в его запрос.

## Сохранённые сценарии

Разговорное управление не отменяет ручные сценарии.

Сохранённый сценарий удобен для повторяемой цепочки, которую хочется запускать одинаково. Разговорный Оркестратор удобен для живой работы, когда последовательность меняется от задачи к задаче.

Оба режима используют одни и те же реальные механизмы выполнения целевых чатов.

## Ограничения текущей версии

Оркестратор пока сознательно не является автономным «суперагентом».

Он не должен сам создавать бесконечные циклы вроде «критикуй и переписывай, пока результат не станет идеальным», не выполняет произвольные if/else-графы и не получает бесконтрольный доступ ко всему приложению.

Это оставляет управление у пользователя и делает расходы, историю и поведение проекта понятнее.
