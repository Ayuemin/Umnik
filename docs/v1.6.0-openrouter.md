# Umnik 1.6.0: OpenRouter Hub

Umnik 1.6.0 расширяет приложение от обычного чат-клиента до универсального Android-интерфейса возможностей OpenRouter. Новые функции не заменяют стандартный чат и не применяются к NVIDIA или произвольным OpenAI-compatible подключениям, если это явно не поддержано их прежней логикой.

## Каталог моделей

OpenRouter Hub загружает общий каталог с `output_modalities=all` и дополняет его специализированными каталогами изображений, видео и embeddings. Вкладка «Все» не накладывает фильтр категории. Отдельно можно фильтровать категории, варианты модели и входные возможности.

Категории: Text, Image, Video, Speech, Transcription, Embeddings, Rerank, Audio.

Варианты: Standard, Batch, Free, Thinking, Extended, Online, Nitro, Floor. Категория описывает, что модель делает; вариант описывает способ или маршрут её использования.

## Batch

`*:batch` не отправляется через обычный `/chat/completions`. Umnik создаёт асинхронное задание через `/api/beta/batches`, сохраняет возвращённый `batch_id` и после этого только опрашивает состояние. Неоднозначная сетевая ошибка POST не приводит к автоматической повторной отправке платного задания.

В обычном чате выбор Batch-модели автоматически использует Batch API. Для нескольких независимых задач есть вкладка «Задания» в OpenRouter Hub; задания разделяются строкой `---`. В меню `+` кнопка Batch активна только при выбранной Batch-модели.

## Фоновые задания

Batch и Video имеют локальные записи job ID. WorkManager восстанавливает опрос после перезапуска процесса, но не создаёт новую платную задачу. Готовые результаты добавляются в исходный чат без повторной доставки одного и того же job.

## RAG, Embeddings и Rerank

RAG включается вручную и по умолчанию выключен. Для текстовых вложений Umnik делает временное смысловое разбиение, получает embeddings, выбирает подходящие фрагменты и при наличии rerank-модели переранжирует кандидатов. Выбранные фрагменты помечаются как пользовательские данные, а не инструкции. Мастер-инструкция проекта остаётся выше файлов по приоритету.

В 1.6.0 индекс строится для текстового контекста текущего запроса и не является постоянной локальной векторной базой. PDF и другие нетекстовые файлы продолжают использовать существующую передачу OpenRouter. Это сознательное ограничение первого релиза RAG, чтобы не хранить устаревшие embeddings после изменения файлов.

## Audio и Video

Hub позволяет выбрать модели Transcription и Speech для STT/TTS. Видео создаётся через асинхронный Video API; можно приложить до четырёх image/video/audio референсов. Готовый MP4 скачивается в локальное хранилище Umnik.

## Responses, Files и Shell

Shell использует Responses API. Выбранные файлы временно загружаются через Files API, передаются в контейнер OpenRouter, а найденные созданные файлы скачиваются в `generated`. Загруженные для задания исходники удаляются из Files API после завершения попытки.

## Server tools

Доступны Web Search, Web Fetch, DateTime, Image Generation, Fusion, Advisor, Subagent и Shell. Shell переключает обычный OpenRouter-чат на Responses API; остальные поддерживаемые server tools добавляются к запросу Chat Completions.

## Маршрутизация и приватность

OpenRouter Hub позволяет задать sort по price/throughput/latency, provider order/only/ignore, fallback-модели, ZDR, запрет data collection, допустимые квантизации и верхние границы цены. Эти параметры сохраняются локально и добавляются только в запросы OpenRouter.

## Метаданные ответа

Для обычных ответов OpenRouter Umnik сохраняет значения, фактически возвращённые API: модель, провайдер, prompt/completion tokens и стоимость, если она присутствует. Приложение не рассчитывает стоимость самостоятельно по потенциально устаревшему прайсу.

## Совместимость

Формат сохранённых сообщений расширен только nullable-полями с значениями по умолчанию, поэтому старые чаты не требуют миграции. Логика проектов и навыков остаётся универсальной; новые возможности OpenRouter не добавляют предметных правил в системный промпт.
