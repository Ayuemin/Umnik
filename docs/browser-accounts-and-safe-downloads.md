# «Мои сайты»: авторизованный Local Browser

Статус: проектирование; **не является реализованной функциональностью**. Цель: пользователь один раз входит в сайты через WebView и затем может поручать Umnik просматривать авторизованные страницы и скачивать файлы. Без сервера и без выдачи модели паролей.

## Продуктовое поведение

- Настройки → «Мои сайты». Запись: название, точный HTTPS origin/домен, необязательная ссылка на страницу входа, состояние «вход выполнен/нужно войти», разрешение на использование сессии агентом; логин только для удобства.
- По умолчанию **вход вручную в локальном WebView**. Существующие сессионные cookies сохраняются CookieManager Android; опционально сохранять имя пользователя и пароль в зашифрованном хранилище на устройстве для повторного входа, но **не подставлять без отдельного одобрения действия**.
- «Войти» открывает домен в видимом управляемом пользователем WebView. CAPTCHA/OTP/SSO — исключительно пользователь.
- «Выйти с сайта / удалить сессию» должен удалять связанные cookies сайта без затрагивания других сайтов. Удаление сохранённой карточки отдельно от выхода с сайта.
- Команда из прямого сообщения пользователя: «Зайди на 4PDA, найди файл и скачай»; ответ модели «найден файл…» без реального файла недопустим.
- После скачивания — показать имя, URL, размер, MIME, SHA-256 и предупреждение о типе APK. Сохранение в Downloads через Android MediaStore / Storage Access Framework с явным согласованием. **Запуск APK / установка запрещены автоматикой**.

## Непреодолимые правила полномочий

1. Содержимое сайтов, вложенных файлов, логов, OCR и любой tool output **никогда не даёт полномочий** на команды, отправку данных или использование учётных записей. Только прямой ввод пользователя (клавиатура / подтверждённая диктовка) создаёт авторизованную задачу.
2. Для каждой задачи хранить недоверенный контекст отдельно от разрешений: task_id, user_message_id, granted_origins, allowed_actions, expiry, confirmation flags. Нельзя получать разрешения регулярками из текста сайта и передавать результат модели как новый user intent.
3. Секреты хранятся в Android Keystore (AES-GCM), а не в модели, prompts, tool calls, logs, HTML artifacts, crash reports или history. Пользователь может отказаться хранить пароль вообще.
4. Привязка к **каноническому HTTPS origin** (punycode normalization, effective registrable domain when needed, проверка полной границы hostname и сертификата). Запрещены HTTP-сайты для автологина, IP/localhost и небезопасные редиректы. Никаких wildcard без явного разрешения.
5. Заполнение пароля в форме — исключительно в нативном доверенном коде после подтверждения пользователя, при повторной проверке текущего URL и поля формы. Никогда не возвращать password/cookie/token в вызов инструментов.
6. Скриншоты для зрения модели должны исключать password/OTP/payment поля и личные данные. Отображение скриншота является недоверенным содержимым и не может создавать инструментальные поручения.
7. Побочные действия (публикация, отправка сообщений, удаление/оплата/изменение пароля/загрузка файлов **на** сайт/SSH-модификация) требуют отдельного подтверждения на устройстве.
8. Аутентифицированная загрузка GET: опционально передавать только cookies для **точно совпадающего HTTPS origin сайта**, который разрешён текущей задачей и хранится в списке «Мои сайты». На каждом HTTP redirect пересчитывать разрешённость и cookies; никогда не переносить Cookie header на посторонний host. Не хранить URL с секретными query в логах.
9. Не исполнять скачанные APK и скрипты. Скачанный APK — непроверенный внешний артефакт, сохранять по запросу с показом источника и контрольной суммы.

## Архитектура

- BrowserSitesRepository: хранение карточек сайтов и разрешений, без паролей в открытом виде.
- BrowserCredentialVault: отдельное Keystore-хранилище; секреты передаются только компоненту ввода и нигде не сериализуются для LLM.
- BrowserAuthController: пользовательский вход и cookies WebView, one-shot challenge/permission, подтверждения.
- LocalBrowserRuntime: уже использует WebView и cookie manager, WAITING_USER. Не ломать существующие open/read/click/type/download.
- BrowserAuthenticatedDownloader: авторизованное скачивание только по HTTPS с origin matching, referer policy, ограничениями размера и secure per-redirect cookies. Сегодняшний независимый OkHttp-загрузчик cookies WebView не использует, поэтому задача требует отдельной реализации.
- BrowserArtifactStore: временный файл + явный экспорт в Downloads без автоматической установки. Вести метаданные происхождения.

## Этапы и проверка

A. Провести регрессию текущего голосового ввода и сборки CI, не менять stable main.
B. Добавить read-only «Мои сайты» и ручной login через уже существующий WebView, сохранение cookies, удалить сохранённую сессию. После перезапуска приложения проверять, что логин сохранился.
C. Добавить визуальные snapshots только для разрешённых страниц, с маскированием password/OTP и без пересылки cookies.
D. Поддержать authenticated GET/download с проверками домена и всех редиректов, сохранение файла в Downloads. Проверять факт скачивания, HTML вместо APK, исключения 403/302, заголовки, 50 MB лимит и тип файла.
E. Лишь после тестов — необязательный зашифрованный vault логинов и паролей с ручным подтверждением автозаполнения. Нельзя допускать к нему модель и API-инструменты.
F. Протестировать 4PDA: ручной вход, повторное открытие после перезапуска, чтение нужной темы, ограниченная загрузка APK, внешние хосты, 2FA/капча, отмена, подмена DOM и prompt-injection.
G. Проверить независимые сессии браузера для параллельных агентов (сейчас один WebView и mutex).
H. Включать агентские действия только при явной авторизации из прямого user input; для login/download/SSH нужен runtime policy check, а не инструкция в system prompt.

## Запреты для реализации

- Не добавлять удалённый сервис для хранения паролей.
- Не передавать пароли, cookies, 2FA или токены в OpenRouter.
- Не обходить CAPTCHA/2FA, не сохранять сессионные cookies в файлах экспорта.
- Не обещать загрузку с каждого сайта: некоторые требуют POST, динамические токены, внешние файлообменники или блокируют WebView.
