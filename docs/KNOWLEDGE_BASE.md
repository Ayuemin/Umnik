# Базы знаний Umnik

База знаний предназначена для больших материалов, которые нужны модели регулярно, но которые неудобно отправлять целиком при каждом запросе.

Типичные примеры:

- книги;
- справочники;
- документация;
- методички;
- большие наборы заметок.

## Где используется

В Umnik 1.18 база знаний может принадлежать:

- обычному чату;
- конкретному агенту проекта.

В новой агентной архитектуре проект сам по себе не раздаёт одну общую базу всем специалистам. Если двум агентам нужен один и тот же источник, он должен быть добавлен в рабочую среду каждого нужного агента.

## Чем база знаний отличается от постоянного файла

Постоянный файл удобно использовать для небольшого документа, который модели полезно видеть целиком.

База знаний использует RAG:

1. Umnik извлекает текст;
2. делит его на фрагменты;
3. получает embedding-векторы через OpenRouter;
4. хранит источник, фрагменты и индекс локально;
5. при вопросе ищет подходящие по смыслу фрагменты;
6. передаёт основной модели только найденные места.

Большой документ поэтому не отправляется основной модели целиком при каждом запросе.

## Изоляция базы агента

База знаний агента принадлежит только ему.

Другой агент не получает к ней доступ автоматически. Если Оркестратор передаёт результат первого агента второму, это не открывает второму исходную базу знаний первого.

Так можно дать разным специалистам разные профессиональные источники.

## Поддерживаемые материалы

Поддерживаются текстовые документы и форматы, для которых Umnik умеет извлекать текст, включая PDF с текстовым слоем, EPUB, DOCX, TXT, Markdown, HTML/XML, JSON/CSV/YAML и текстовые файлы кода.

Сканированный PDF без текстового слоя автоматически не распознаётся: встроенного OCR для него пока нет.

## Embeddings и приватность

Индекс хранится локально, но создание embeddings выполняется через OpenRouter.

При индексации текстовые фрагменты отправляются в OpenRouter Embeddings. При поиске туда же отправляется текст поискового запроса. Сопоставление с локальным индексом и выбор результатов выполняются на устройстве.

Поэтому база знаний не является полностью офлайн.

## Настройки

Для базы можно выбрать embedding-модель, включить или выключить поиск и настроить количество возвращаемых фрагментов.

Источник можно переиндексировать другой embedding-моделью.

## Защита от инструкций внутри источников

Найденные фрагменты добавляются как справочные данные, а не как управляющие команды.

Основная модель получает указание не выполнять инструкции, случайно или намеренно находящиеся внутри цитируемого источника. Это снижает риск prompt injection, но не устраняет его полностью.
