# Базы знаний Umnik

База знаний предназначена для больших материалов, которые нужны модели регулярно, но которые неудобно отправлять целиком при каждом запросе.

Для работы базы один раз задаются общие служебные модели в **Настройки → Модели**: **Системная модель** понимает естественные запросы и продолжения, а **Embeddings-модель** отвечает за смысловой индекс.

## Где используется

База знаний в Umnik может принадлежать:

- обычному чату;
- конкретному специалисту команды.

Команда сама по себе не раздаёт одну общую базу всем специалистам. Если двум специалистам нужен один и тот же источник, он добавляется в рабочую среду каждого нужного специалиста.

Будущий **Проект** — отдельная зарезервированная сущность и сможет получить собственную общую базу знаний только после отдельной реализации.

## Чем база знаний отличается от постоянного файла

Постоянный файл удобно использовать для небольшого документа, который модели полезно видеть целиком.

База знаний использует RAG:

1. Umnik извлекает текст;
2. делит его на фрагменты;
3. получает embedding-векторы через OpenRouter;
4. хранит источник, фрагменты и индекс локально;
5. при вопросе ищет подходящие по смыслу фрагменты;
6. передаёт основной модели только найденные места.

Большой документ поэтому не отправляется основной модели целиком при каждом запросе.

## Изоляция базы специалиста

База знаний специалиста принадлежит только ему.

Другой специалист не получает к ней доступ автоматически. Если Оркестратор передаёт результат первого специалиста второму, это не открывает второму исходную базу знаний первого.

## Поддерживаемые материалы

Поддерживаются текстовые документы и форматы, для которых Umnik умеет извлекать текст, включая PDF с текстовым слоем, EPUB, FB2, DOCX, TXT, Markdown, HTML/XML, JSON/CSV/YAML и текстовые файлы кода.

Сканированный PDF без текстового слоя автоматически не распознаётся: встроенного OCR для него пока нет.

## Embeddings и приватность

Индекс хранится локально, но создание embeddings выполняется через OpenRouter.

При индексации текстовые фрагменты отправляются в OpenRouter Embeddings. При запросе системная модель сначала подготавливает поисковую формулировку с учётом недавнего диалога, затем этот запрос отправляется в OpenRouter Embeddings. Сопоставление с локальным индексом и выбор результатов выполняются на устройстве.

## Настройки

Внутри конкретной базы остаётся только её включение или выключение и управление документами.

**Системная модель** и **Embeddings-модель** задаются один раз в **Настройки → Модели**. После смены Embeddings-модели Umnik запускает переиндексацию документов и перестройку зависимых векторных индексов.

## Защита от инструкций внутри источников

Найденные фрагменты добавляются как справочные данные, а не как управляющие команды.

Основная модель получает указание не выполнять инструкции, находящиеся внутри цитируемого источника. Это снижает риск prompt injection, но не устраняет его полностью.


## Самостоятельный поиск модели

Для моделей с поддержкой tool calling Umnik может дополнительно предоставить локальный инструмент `knowledge_search`.
Это не заменяет обычный RAG и не меняет назначение базы знаний.

База остаётся доступна в двух сценариях:

- пользователь прямо задаёт вопросы по загруженным документам;
- совместимая модель сама обращается к базе во время выполнения любой задачи, когда ей нужны дополнительные сведения.

Для каждой базы можно задать необязательную короткую инструкцию о том, когда и как модели самой использовать поиск.
Если поле пустое, модель решает это самостоятельно. Инструкция не должна превращать базу в узкоспециализированный сценарий:
содержимое базы может быть любым — правила, справочники, техническая документация, книги, процедуры, примеры и другие материалы.

Самостоятельный поиск ограничен несколькими обращениями за один ответ и кэширует повторные одинаковые запросы,
чтобы модель не вызывала базу бесконечно и не тратила embeddings повторно без необходимости.
