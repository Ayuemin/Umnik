# Базы знаний Umnik

База знаний предназначена для больших материалов, которые нужны ИИ-специалисту постоянно, но которые слишком дорого и неудобно отправлять целиком при каждом запросе.

Типичные примеры:

- книги;
- учебники;
- справочники;
- документация;
- методички;
- большие наборы заметок;
- внутренние материалы проекта.

## Чем база знаний отличается от постоянного файла

Постоянный файл добавляется в обычный рабочий контекст чата или проекта. Это удобно для короткого ТЗ, небольшой инструкции или документа, который модели действительно полезно видеть целиком.

База знаний использует RAG: большой источник индексируется один раз, а при каждом запросе Umnik автоматически находит только несколько наиболее релевантных фрагментов.

Проще говоря:

**постоянный файл = «держи этот документ рядом»**

**база знаний = «знай эту библиотеку и доставай из неё нужные места по запросу»**

## Как работает RAG в Umnik

При добавлении документа:

1. Umnik извлекает текст;
2. разбивает его на небольшие фрагменты;
3. отправляет фрагменты в OpenRouter Embeddings;
4. получает embedding-векторы;
5. сохраняет исходник, фрагменты, метаданные и векторы локально на устройстве.

При новом вопросе:

1. текст вопроса отправляется в OpenRouter Embeddings;
2. Umnik сравнивает embedding вопроса с локальным индексом;
3. выбирает несколько наиболее близких по смыслу фрагментов;
4. добавляет только эти фрагменты в системный контекст основной модели;
5. основная модель отвечает, используя найденные материалы.

Поэтому большая книга не отправляется основной модели заново при каждом сообщении.

## Два уровня базы знаний

### База проекта

Доступна чатам этого проекта.

Подходит для общих материалов:

- документации продукта;
- требований;
- общего справочника;
- внутренней базы фактов;
- единого учебного материала.

### База конкретного чата

Принадлежит одному ИИ-специалисту.

Например:

- Дизайнер - книги по UX/UI;
- Редактор - книги по редактуре;
- Программист - техническая документация;
- Маркетолог - учебники и исследования по маркетингу.

Если одновременно есть база проекта и база чата, Umnik может искать релевантные фрагменты в обоих источниках.

## Поддерживаемые форматы

В версии 1.14.0 поддерживаются:

- PDF с текстовым слоем;
- EPUB;
- DOCX;
- TXT;
- Markdown;
- HTML;
- XML;
- JSON;
- CSV;
- YAML;
- текстовые файлы кода.

Для PDF сохраняется номер страницы, поэтому найденный фрагмент можно связать с конкретным местом источника.

### Сканированные PDF

Если PDF состоит только из изображений страниц и не содержит текстового слоя, обычное текстовое извлечение не поможет.

В текущей версии Umnik не делает OCR таких документов автоматически. Для них потребуется отдельная OCR-поддержка в будущем.

## Настройки

Для каждой базы можно выбрать:

- embedding-модель;
- автоматический поиск по базе при запросах;
- количество найденных фрагментов: 3, 5 или 8.

По умолчанию используется `qwen/qwen3-embedding-8b`.

Документ можно переиндексировать другой embedding-моделью без повторного ручного добавления файла.

## Стоимость

Embeddings обычно заметно дешевле полноценного запроса к большой генеративной модели.

Основная экономия появляется потому, что большой документ индексируется один раз, а затем основной модели передаются только несколько релевантных фрагментов вместо сотен страниц.

Фактическая цена зависит от выбранной embedding-модели и текущих тарифов OpenRouter.

## Приватность

Важно понимать границу локального хранения.

Локально на устройстве Umnik хранит:

- исходный импортированный документ;
- извлечённый текст;
- фрагменты;
- embedding-векторы;
- индекс;
- метаданные источника.

Но создание embeddings не является полностью локальным: при индексации текстовые фрагменты отправляются в OpenRouter для вычисления векторов.

При поиске по базе текст текущего поискового запроса также отправляется в OpenRouter для получения embedding.

После этого сравнение с индексом и выбор фрагментов происходят локально. Основной модели передаются только найденные фрагменты, а не вся книга.

Подробнее о данных: [../PRIVACY.md](../PRIVACY.md).

## Защита от инструкций внутри источников

Найденные фрагменты добавляются в контекст как **справочные данные**, а не как команды.

Модель получает явную инструкцию не исполнять команды, случайно или намеренно содержащиеся внутри цитируемого документа. Это снижает риск prompt injection из базы знаний, хотя полностью устранить такой класс рисков невозможно.

## Работа с Оркестратором

База знаний работает и когда чат запускается не вручную, а через ◆ Оркестратор.

Например:

> Дизайнер пусть предложит новый экран настройки проекта, используя свою базу знаний. Потом передай решение Критику.

Umnik сначала выполнит семантический поиск по базе Дизайнера, передаст подходящие фрагменты его модели, а затем Оркестратор сможет передать полученный результат следующему исполнителю.

## Практический совет

Не стоит складывать в одну базу всё подряд.

Лучше делать базы тематическими. Тогда семантический поиск точнее и понятнее:

- общие материалы продукта - в базе проекта;
- профессиональные книги специалиста - в базе его чата;
- короткие текущие инструкции - в постоянных файлах или мастер-промпте.
