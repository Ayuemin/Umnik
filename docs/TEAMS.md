# Команды в Umnik

**Команда** — это Оркестратор и набор независимых ИИ-специалистов.

Термин «Проект» для этой сущности больше не используется. Он зарезервирован для будущего рабочего пространства с несколькими чатами, общей базой знаний, файлами и, возможно, общей памятью.

## Основной принцип

Сама команда не раздаёт участникам общую инструкцию, навыки, файлы или базу знаний.

Каждый специалист настраивается отдельно и имеет собственные:

- имя и роль;
- личную инструкцию;
- основную модель;
- дополнительные модели чатов;
- reasoning;
- веб-поиск;
- навыки;
- постоянные файлы;
- базу знаний;
- историю разговора и память.

Системная модель и Embeddings-модель являются общими служебными настройками Umnik и задаются один раз в **Настройки → Модели**.

## Что находится в команде

Внутри команды есть:

- Оркестратор;
- один или несколько специалистов;
- отдельный разговор каждого специалиста;
- рабочее пространство текущих поручений Оркестратора.

Оркестратор управляет работой. Специалисты выполняют поручения. Имена специалистов произвольны: поведение определяется их ролью, инструкцией, моделью и текущей задачей.

## Создание специалиста

Откройте команду и нажмите **Новый специалист**.

Минимально нужно выбрать основную модель. Дополнительно можно настроить роль, инструкцию, reasoning, веб-поиск, навыки, файлы, базу знаний и режим контекста.

После сохранения можно открыть разговор специалиста и работать с ним напрямую, без Оркестратора.

## Изоляция

Специалист автоматически не видит:

- навыки другого специалиста;
- его постоянные файлы;
- его базу знаний;
- его память;
- его историю разговора;
- настройки обычных чатов.

Если следующему специалисту нужен результат предыдущего, Оркестратор передаёт рабочий результат конкретного задания.

## Оркестратор

Пользователь пишет Оркестратору поручение обычным языком. Например:

> Пусть два специалиста независимо разберут материал. После этого передай оба результата третьему специалисту, чтобы он собрал общий вывод.

Независимые задачи могут выполняться параллельно. Зависимый шаг запускается после получения требуемых результатов.

Подробнее: [ORCHESTRATOR.md](ORCHESTRATOR.md).

## Предпусковая диагностика

Перед первым запуском команды и после изменения её конфигурации Umnik локально проверяет критичные настройки. Проверка не вызывает ИИ-модель и не расходует баланс OpenRouter.

Проверяются:

- основная модель Оркестратора;
- основные модели специалистов;
- существование и состояние подключения;
- наличие API-ключа;
- наличие общей системной модели, если используются базы знаний;
- наличие хотя бы одного специалиста;
- доступность локальных файлов и настроек.

Если запуск невозможен, Umnik сообщает, у какого специалиста чего не хватает.

## Ошибка одного специалиста

Ошибка одного поручения не должна уничтожать уже завершённую работу остальных специалистов.

Успешный результат сохраняется отдельно. Неудачное поручение получает статус FAILED и причину ошибки. Уже завершённое поручение не должно автоматически выполняться заново.

## Файлы и база знаний

Короткие постоянные материалы можно прикреплять непосредственно к специалисту.

Большие книги, справочники и документацию удобнее добавлять в его базу знаний. Тогда Umnik выполняет смысловой поиск и передаёт основной модели только подходящие фрагменты.

Подробнее: [KNOWLEDGE_BASE.md](KNOWLEDGE_BASE.md).

## Очистка и удаление

Историю разговора специалиста можно очистить отдельно от его настроек.

При очистке сохраняются профиль, модели, навыки, файлы и база знаний. Удаление самого специалиста удаляет его локальную рабочую среду. Оркестратор удаляется только вместе с командой.

## Совместимость со старыми данными

Переименование не должно терять уже созданные сущности.

Umnik читает старые поля и хранилища `projects` / `agents`, `projectId` / `agentId` и переносит их в новую схему `teams` / `specialists`. Legacy-данные удаляются только после успешного переноса.
