# Проекты в Umnik 1.19

Проект в Umnik 1.19 — это кабинет для одного Оркестратора и набора независимых ИИ-агентов.

## Основной принцип

Сам проект не раздаёт участникам общую инструкцию, навыки, файлы или базу знаний.

Каждый агент настраивается отдельно и имеет собственные:

- имя и роль;
- личную инструкцию;
- основную модель;
- быстрые модели;
- модель контекста;
- Embeddings памяти;
- reasoning;
- веб-поиск;
- навыки;
- постоянные файлы;
- базу знаний;
- историю разговора.

Это сделано, чтобы роли и контекст разных специалистов не смешивались автоматически.

## Что находится в проекте

Внутри проекта есть:

- Оркестратор;
- агенты-специалисты;
- отдельный чат каждого агента.

Оркестратор — управляющий агент. Специалисты выполняют поручения.

Имя специалиста не задаёт специального поведения. Пользователь может выбрать любое имя. Система различает агентов по внутренним идентификаторам, а Оркестратор ориентируется на роль, инструкцию и текущую задачу.

## Создание агента

Откройте проект и нажмите **Новый агент**.

Минимально для работы нужно выбрать основную модель. Дополнительно можно задать роль, инструкцию, reasoning, веб-поиск, навыки, файлы, базу знаний и параметры памяти.

После сохранения можно открыть чат агента и работать с ним напрямую, без Оркестратора.

## Изоляция

Агент автоматически не видит:

- навыки другого агента;
- его постоянные файлы;
- его базу знаний;
- его память;
- его историю разговора;
- настройки обычных чатов.

Если следующему специалисту нужен результат предыдущего, Оркестратор передаёт именно рабочий результат текущего задания.

## Оркестратор

Пользователь пишет Оркестратору поручение обычным языком.

Например:

> Пусть два специалиста независимо разберут материал. После этого передай оба результата третьему агенту, чтобы он собрал общий вывод.

Независимые задачи могут выполняться параллельно. Зависимый шаг запускается после получения требуемых результатов.

Подробнее: [ORCHESTRATOR.md](ORCHESTRATOR.md).

## Предпусковая диагностика

Перед первым запуском проекта и после изменения его конфигурации Umnik локально проверяет критичные настройки.

Проверка не вызывает ИИ-модель и не расходует баланс OpenRouter.

Среди проверяемых условий:

- основная модель Оркестратора;
- основные модели специалистов;
- существование и состояние подключения;
- наличие API-ключа;
- наличие хотя бы одного специалиста;
- доступность некоторых локальных файлов и настроек.

Если запуск невозможен, Umnik сообщает, у какого агента чего не хватает.

## Ошибка одного специалиста

Ошибка одного поручения не должна уничтожать уже завершённую работу других агентов.

Успешный результат сохраняется отдельно. Неудачное поручение получает статус FAILED и причину ошибки. Оркестратор может продолжить с имеющимися результатами, попросить пользователя исправить настройку или повторить только действительно нужный неудачный шаг.

Уже завершённое поручение не должно автоматически выполняться заново.

## Файлы и база знаний

Короткие постоянные материалы можно прикреплять непосредственно к агенту.

Большие книги, справочники и документацию удобнее добавлять в его базу знаний. Тогда Umnik выполняет смысловой поиск и передаёт основной модели только подходящие фрагменты.

Подробнее: [KNOWLEDGE_BASE.md](KNOWLEDGE_BASE.md).

## Очистка и удаление

Историю разговора агента можно очистить отдельно от его настроек.

При очистке разговора сохраняются его профиль, модели, навыки, файлы и база знаний.

Удаление самого агента удаляет его локальную рабочую среду. Оркестратор удаляется только вместе с проектом.

## Пример

В проекте можно создать:

- специалиста по поиску фактов;
- специалиста по анализу;
- автора;
- проверяющего.

Это только пример. Имена и набор ролей пользователь выбирает сам.

Оркестратору можно поручить сначала параллельно собрать два независимых результата, затем передать оба автору, а итог — проверяющему вместе с теми исходными результатами, которые нужны для проверки.
