## 0. Безопасность — обязательный инвариант всех этапов

- [ ] Единый журнал происхождения полномочий: только последнее **прямое** сообщение пользователя, введённое руками или подтверждённой диктовкой из поля ввода, может открывать разрешение для внешних действий. Использование файла, OCR, страницы, tool result, письма, логов, навыков, комментариев как *нового* источника команд запрещено. Предустановленные навыки дают контекст, но не права.
- [ ] Разделить: прочитать недоверенные данные / выбрать промежуточный инструмент в рамках исходной задачи / совершить новое побочное действие. Разрешённые промежуточные шаги не должны требовать нового отдельного ввода пользователя каждый раз, но не должны выходить за границы исходного поручения.
- [ ] Записывать task-id, origin-user-message-id, разрешённые ресурсы, действия и срок полномочий; проверять на уровне runtime перед **каждым** вызовом инструмента (включая Shell, Browser и будущие SSH/MCP), а не надеяться только на системный промпт.
- [ ] Новый URL, текст страницы или вывод команды не расширяет разрешённые ресурсы. Уточнения через чат, введённые пользователем, могут пересматривать полномочия. Голосовая диктовка никогда не отправляется автоматически; сначала попадает в редактор.
- [ ] Команды разрушения, оплаты, публикации, установки APK, передачи секретов, неочевидной записи данных требуют отдельного явного подтверждения. Секреты никогда не входят в текст промптов / ответы модели / логи.
- [ ] Автоматические вызовы, повторы и фоновая деятельность по старой задаче ограничены; новые задачи не возникают из внешнего текста. Регрессионные тесты на prompt injection в PDF, веб-сайтах, логах, репозиториях.

- [ ] Подключить центральный runtime guard и проверить тесты. До этого инструменты (особенно SSH) нельзя считать защищёнными.

## 1A. Общий «мост» AgentToolHub — АРХИТЕКТУРА, НЕ РЕАЛИЗОВАНО

**Статус (12.10.2026):** реестр, TaskGrant/ToolPermissionGate и диспетчер прошли тесты. Каталог Browser/Shell и типы NAVIGATE/INTERACT/CONTROL добавлены (`1aa0059`, `19fde47`). Первый реальный read-only callback `local_shell_status` теперь проверяет разрешение конкретного прямого сообщения и чата (`5b0410c`). Полный Browser и запуск Local Shell **ещё не подключены** к новой защите, считать их защищёнными AgentToolHub пока нельзя.

**Цель:** все разрешённые инструменты доступны одному агенту в одном поручении;
агент может объединять их последовательно и выполнять независимые операции
параллельно. Новый инструмент присоединяется как стандартный адаптер, а
не дописывается в гигантский класс. Не начинать до приёмки диктовки.

- [ ] `AgentToolHub` — компактный фасад, `ToolRegistry` — каталог
  инструментов, `ToolAdapter` — одинаковый контракт для каждой интеграции.
- [ ] `TaskCoordinator` — план шагов и зависимостей, параллельные задачи,
  прогресс, отмена, таймауты и устойчивое восстановление после сбоев.
- [ ] `ToolPermissionGate` — перед каждым реальным действием проверять
  `TaskGrant` из прямого пользовательского поручения, без повышения прав
  из сайтов, файлов, моделей и результатов инструментов.
- [ ] `ArtifactStore` — безопасная передача файлов между инструментами по
  идентификаторам, без передачи бинарных данных и секретов модели.
- [ ] `ToolSessionManager` — независимые сессии Browser/SSH, ограничение
  конкурентности и исключение гонок.
- [ ] Сначала подключить существующие Local Shell/Local Browser без регрессии;
  затем добавлять SSH, GitHub, облака, заметки, почту и прочие адаптеры.
- [ ] Проверка: Browser → файл → Shell → облако; параллельно SSH + GitHub;
  сбой/отмена/перезапуск; prompt injection и отсутствие утечки секретов.
- [ ] Архитектуру дробить на небольшие файлы согласно `AGENTS.md`,
  **никакого нового монолитного суперкласса**.

Подробное описание: `docs/agent-tool-hub-architecture.md`.
Этап внедряется постепенно вместе со следующими инструментами, не отдельной
массовой переписью приложения. Стабильную `main` не менять.

## 4. «Подключение агента» — ПЛАН, НЕ РЕАЛИЗОВАНО

**Единый раздел настроек** со списком подключений и тремя отдельными типами, с возможностью расширения. Не смешивать модельные провайдеры OpenRouter/Polza.ai с подключениями к внешним ресурсам:

- [ ] **Сайт / браузерная сессия:** название, канонический HTTPS origin, страница входа, ручная авторизация через WebView, сохранённые cookies. По желанию — логин и пароль только в защищённом локальном хранилище; CAPTCHA/OTP/SSO передаются пользователю.
- [ ] **API:** GitHub и другие сервисы через API-токен, PAT, OAuth (если поддерживается провайдером). Выбор конкретного API-коннектора и его URL/базового адреса, scope, разрешённых методов, лимитов; не создавать универсальную возможность произвольной отправки HTTP с секретом.
- [ ] **SSH / SFTP:** название хоста, hostname/IP, порт, имя пользователя, SSH private key + passphrase (опционально), при поддержке — парольная авторизация. Host-key pinning, предупреждение при изменении ключа сервера, отдельные read-only и mutation-разрешения, таймауты и ограничения на команды/файлы. Конфигурацию SSH не считать веб-сайтом.
- [ ] Для API-токена, пароля сайта, passphrase и приватного SSH-ключа использовать шифрованное локальное хранилище с защитой ключей через Android Keystore. **Никакие секреты не отправлять в OpenRouter, историю чата, tool result, MCP/LLM context, логи, скриншоты и файлы экспорта.** Агент получает только opaque connection ID и допустимые операции; конкретный секрет использует локальный адаптер.
- [ ] Пользователь явно включает каждое подключение и отдельно разрешает категории операций: чтение, скачивание, изменение, публикация, удаление. Новый подключённый сервис по умолчанию закрыт для агента до разрешения.
- [ ] API/SSH: для действий с побочными эффектами требовать подтверждение пользователя, не доверять произвольным командам из веб-страниц, кода, ответов серверов или tool output. Не давать LLM самостоятельно расширять scopes, изменять список разрешённых хостов или экспортировать креденшелы.
- [ ] Управление жизненным циклом: проверить соединение без выдачи секретов, отключить, отозвать токен/ключ, удалить запись, завершить браузерную сессию; эти операции не затрагивают остальные подключения.
- [ ] **Сайтовые загрузки:** авторизованный downloader с cookies только разрешённому origin, повторной проверкой каждого redirect, детектированием HTML вместо ожидаемого APK и сохранением через MediaStore / системный выбор Downloads; никакой автоматической установки APK.
- [ ] **MCP:** в будущем внешние инструменты могут ссылаться на connection ID, но не получать сырые пароли/токены/SSH-ключи. Ограничения и подтверждения проверяет основной runtime, а не модель.
- [ ] Тестовые сценарии: 4PDA login → скачать APK; GitHub API → прочитать issue/репозиторий с ограниченным токеном; SSH по ключу → прочитать логи; SFTP → скачать файл; запрет SSH-команд после prompt injection в логах и браузере.

**Порядок:** доработка этого раздела пока не начинается: сначала полный приёмочный цикл диктовки, затем визуальный Browser, затем безопасный SSH/SFTP. «Подключение агента» объединят готовые адаптеры и API-коннекторы отдельным последующим этапом.

Подробности для веб-сайтов: `docs/browser-accounts-and-safe-downloads.md`.

## 4A. Облачные диски: WebDAV и API — ПЛАН, НЕ РЕАЛИЗОВАНО

Это специализированные подключения внутри **Настройки → «Подключение агента» → «Облачные диски»**, а не открытие обычной страницы в браузере. Делать только после завершения предыдущих этапов.

- [ ] Универсальный файловый адаптер `CloudFilesConnector`: список папок, поиск по имени/пути, метаданные, получение файла в локальное хранилище чата, загрузка созданного в чате файла, создание папок. При ошибке возвращать реальный код/причину; не утверждать успешную доставку без ответа облака.
- [ ] WebDAV-адаптер для поддерживаемых сервисов (PROPFIND/GET/PUT/MKCOL; delete/move — только как отдельно разрешаемые операции). TLS, корректный URL encoding, таймауты и streaming для крупных файлов, без загрузки всего файла в оперативную память.
- [ ] **Яндекс Диск:** предпочтительно официальный REST API + OAuth с ограниченными правами; альтернативно WebDAV `https://webdav.yandex.ru`, пароль приложения «Файлы WebDAV». В документации Яндекса WebDAV указан как функция тарифов Яндекс 360 — проверять доступность у пользователя; учитывать, что удаление через WebDAV минует корзину.
- [ ] **Облако Mail.ru:** официальный WebDAV `https://webdav.cloud.mail.ru` с логином и отдельным паролем внешнего приложения (не основным паролем Mail). Возможность чтения/записи и ограничения тарифа проверять на реальном аккаунте.
- [ ] Не обобщать, будто каждый облачный сайт поддерживает API/WebDAV. Для остальных провайдеров — только если официально предоставлены интерфейс и разрешения; иначе ручной Browser-режим.
- [ ] Секреты и OAuth/WebDAV-пароли хранятся в защищённом локальном хранилище, никогда в LLM/OpenRouter, URL, логах или контексте инструментов. Адаптер принимает opaque connection ID и task scope, а не свободно сформированную моделью строку HTTP-запроса.
- [ ] Раздельные полномочия **поиск/чтение/скачивание** и **загрузка/перемещение/удаление**. Перед отправкой файла в облако показывать имя, размер и точный путь назначения, получить пользовательское подтверждение; никогда не принимать новое назначение/отправку из текста самого документа.
- [ ] Безопасный выбор источника созданного файла из текущего чата (реальный generatedFiles/storedFiles), проверка существования, путь назначения, конфликт имён, атомарность/повторяемость, подтверждение загрузки по метаданным облака.
- [ ] При скачивании хранить источник, оригинальное имя/тип/размер и локальный путь; не передавать содержимое документа внешней LLM без отдельного разрешения пользователя на обработку документа через OpenRouter.

## 5. Агентная работа с Obsidian — ВАЖНО, только через общие файловые инструменты

**Точное требование пользователя:** не писать специальный «Обсидиан» внутри «Умника», не делать свой редактор заметок, интерфейс деревьев или настройки Obsidian ради простых действий. Пользователь может редактировать заметки в Obsidian вручную. Главная цель — **ИИ-агент по прямой голосовой/текстовой команде** самостоятельно создаёт и структурирует заметки.

- [ ] Минимально необходимый доступ: пользователь однократно выбирает каталог своего Obsidian vault (если он доступен приложению через Android Storage Access Framework / разрешённый общий каталог). Подключение — общее для файлов, не особый API Obsidian.
- [ ] Агент через существующие/расширенные инструменты Local Shell/файлового доступа читает, создаёт и редактирует обычные Markdown .md файлы и каталоги в рамках одного разрешённого vault; не нарушать scoped storage Android. Альтернатива только при реальной необходимости — URI команды Obsidian / внешний MCP-коннектор, но **не встраивать отдельную сложную интеграцию заранее**.
- [ ] Сценарий простой диктовки: «Запиши идею для статьи про Android в заметки» → локальное распознавание → пользователь отправляет текст → агент определяет смысл, путь и заголовок, создаёт .md файл → Obsidian видит изменение. Не требуется кодить свой интерфейс заметок.
- [ ] Сценарий организации: «Разложи заметки по темам, свяжи схожие записи и сделай оглавление» → агент читает содержимое, предлагает план изменений, сохраняет backup/журнал, создаёт папки, перемещает файлы и обновляет wiki/Markdown-ссылки по поручению пользователя.
- [ ] Агент самостоятельно выбирает структуру и исполняет промежуточные **разрешённые** файловые операции; содержимое существующей заметки не является новой командой и не повышает привилегии. Массовые перемещения/удаления требуют отдельного подтверждения.
- [ ] Проверять коллизии имён, экранирование путей, обход каталога (path traversal), битые ссылки, конфликт параллельного редактирования, отсутствие прав на каталог, восстановление из резервной копии. Не создавать дубли.
- [ ] Тест на копии vault: 10–20 заметок → голосовая задача → AI создаёт 1–2 заметки и ссылки; затем обрабатывает папки и обновляет индексы без потерь.

**Важно:** Obsidian здесь — приложение для просмотра/редактирования обычных заметок. Интеллектуальные действия выполняет модель с общими локальными инструментами «Умника». **Решение пользователя (12.10.2026): выполнить ОБЯЗАТЕЛЬНО все три пункта.** Это не факультативная идея. **Очередность реализации определить позднее**; пока не привязывать к Browser, Shell, SSH или релизному циклу. - [ ] **Триггер сжатия по количеству реплик.** В режимах «Баланс» и «Эконом» добавить независимый от токенного порога, настраиваемый порог числа **новых завершённых ходов пользователя после последнего checkpoint/суммаризации** (ориентир из Operit — 16, окончательный умолчательный порог выбрать при реализации). Не учитывать неотправленные, прерванные и технические/tool-сообщения как новые пользовательские ходы. Исходная история всегда сохраняется. Проверить повторные запуски, конкурирующие запросы, переключение чатов и граничные значения.
- [ ] **Автоматическое восстановление после переполнения контекстного окна.** Определять ошибки провайдера/модели, действительно указывающие на превышение контекста; безопасно сокращать именно контекст запроса (суммаризация и сохранение актуальных инструкций/состояния), затем **ограниченно повторять** исходный запрос без необходимости ручной пересылки. Не путать ошибку контекста с авторизацией, сетью или лимитом денег. Исключить циклические повторные запросы, потерю текущего текста/вложений, повторное выполнение побочных действий инструментов, удвоение отправок/загрузок, раскрытие секретов и неожиданный рост расходов. При неудаче показать понятную ошибку и сохранить исходное сообщение.

Периодически сворачивать старые подробные результаты инструментов в краткие, проверяемые записи, **не теряя** цель пользователя, разрешения TaskGrant, текущий план, результаты шагов, ошибки, зависимости, ссылки/ID артефактов и незавершённые действия. Сохранять оригинальные результаты локально для точечного повторного чтения, где это возможно. Ни резюме, ни содержимое tools не могут выдавать новые полномочия или инициировать действия вне исходной задачи. Добавить защиту от повторных исполнений после сжатия и при продолжении.

## 9. ОБЯЗАТЕЛЬНО: автономность агента без лишних подтверждений — приоритет UX

**Решение пользователя (12.10.2026):** один прямой запрос пользователя разрешает агенту самостоятельно выполнять **все обычные промежуточные шаги** в пределах поручения, без отдельного подтверждения каждого инструмента или перехода. Это обязательный принцип для существующих Browser/Shell и будущих SSH, SFTP, GitHub, облаков, почты, MCP, файлов и Android-интеграций. **Порядок реализации определить отдельно.** Идею трёх уровней `ALLOW / ASK / FORBID` из Operit использовать только как концептуальную подсказку, чужой код не копировать.

- [ ] **По умолчанию — автоматическое продолжение:** чтение/поиск, обычная веб-навигация, безопасные клики/ввод, промежуточные вычисления, локальные файлы в разрешённой песочнице, подготовка/проверка/упаковка артефактов, создание и редактирование явно запрошенных локальных результатов, безопасные скачивания из разрешённых источников, естественные продолжения длинной задачи. Не делать отдельную модалку на каждый шаг. Не выдавать универсальный сетевой/Shell-доступ: операция обязана соответствовать `TaskGrant` и проверенному реальному ресурсу.
- [ ] **Автономный жизненный цикл сессий:** агент может запускать разрешённые инструменты, поддерживать несколько последовательных шагов и **самостоятельно завершать собственную Browser/Shell/SSH-сессию** или отменять собственную дочернюю задачу. Штатное завершение Local Shell уже автоматически выполняет runtime. Запрещено самостоятельно останавливать чужую/независимую задачу, даже если она в том же чате. Ручные кнопки «Стоп» доступны пользователю независимо от грантов модели.
- [ ] **Подтверждение только для существенных рисков:** деньги, покупка/оплата/финансовое обязательство; необратимое либо массовое удаление и опасная перезапись, особенно на серверах или в облаках; выдача/пересылка секретов и приватных данных третьим сторонам; выдача новых системных прав/изменение границ доступа, доверие новому SSH host key или изменённому ключу; установка ПО/APK; публичная публикация, отправка сообщений или файлов вовне без заранее явно согласованного адресата и содержания; другие труднообратимые последствия. Если прямое поручение уже однозначно разрешает конкретную безопасную операцию, не спрашивать повторно за её технические подшаги.
- [ ] **Browser — снизить ложные запросы подтверждения:** `local_browser_done` завершает свою сессию автоматически; `takeover`/ `WAITING_USER` применять только когда реально нужен человек (пароль, OTP, CAPTCHA, системный выбор файла, чувствительное подтверждение), не как обязательный этап навигации. Сегодня `clickScript` подтверждает многие *неизвестные* клики, а `typeScript` — практически любой POST: пересмотреть классификацию на основании достоверного эффекта и риска, **не ослабляя** защиту оплат/удаления/секретов. Проверять redirects и фактический URL внутри WebView.
- [ ] **Гранты не являются безусловным ALLOW:** решение об обычном автоматическом действии принимается по проверенным `TaskGrant` + реальным целям + риску операции. Текст страницы, API, файла, логов, заметки, вывода Shell или самой модели не может повысить права или отключить подтверждения. Никаких маркеров из аргументов инструмента для обхода gate; нельзя использовать найденный в Operit обход по `deny_tool`.
- [ ] **Проверки удобства и безопасности:** одна задача из 10–20 шагов Browser→файл→Shell→облако без постоянных вопросов; автоматическое завершение своих сессий; невозможность остановить чужой task ID; обычные действия проходят без подтверждений, а оплата, удаление, отправка секрета и изменение хоста блокируются до явного согласия; prompt injection не меняет разрешения. Быстрый и полный CI, тест на устройстве перед закрытием этапа.

**Промежуточная реализация Browser (12.10.2026):** безопасные GET-кнопки поисковых форм теперь допускаются без обязательного подтверждения; `click` распознаёт их `search_navigation`, отслеживает реальный переход/его завершение либо допускает обновление результатов внутри SPA без смены URL (`c89b9ed`, `cc2f3aa`, `c2a530e`). Быстрый CI для исправления ожидания навигации зелёный (`38280115022`). **Это не завершает пункт об автономности**: фактические URL/redirects, проверка TaskGrant внутри WebView, функциональные испытания на Android и остальная классификация действий ещё впереди.

Никаких утверждений «готово» до зелёных GitHub Actions и испытаний на устройстве. Тестовые сборки из work-ветки устанавливаются отдельно от стабильного «Умника». `main` не изменять.

### Режимы Android CI для ускорения работы

- **Обычный push в `work/**`:** быстрый CI — `:app:testDebugUnitTest :app:assembleDebug`, проверка Vosk в APK, публикация отдельного debug-артефакта. Это **не** подтверждение прохождения lint и R8.
- **Контрольный push в `work/**`:** добавить в сообщение коммита маркер `[full ci]`. Тогда выполняется исходный полный цикл `:app:lintDebug :app:testDebugUnitTest :app:assembleDebug :app:assembleRelease` с R8, проверкой Vosk и APK-артефактом.
- **Push в `main` и pull request в `main`:** полный цикл автоматически.
- **После завершения каждого функционального этапа** обязательно подтверждать зелёный полный CI перед испытанием на реальном Android или следующей крупной интеграцией. «Зелёный быстрый» не заменяет «зелёный полный».
- Для Gradle включён build cache и запись branch-scoped кеша в `work/**`. Не отключать тесты, R8 и проверки безопасности в контрольных сборках.
- Существующие подписанные релизы, F-Droid и стабильная `main` этой настройкой не изменяются.
