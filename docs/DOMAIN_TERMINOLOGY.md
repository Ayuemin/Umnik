# Терминология домена Umnik

Этот документ фиксирует названия сущностей, чтобы новые функции не заняли старые имена повторно.

| Термин | Значение |
|---|---|
| **Чат** | обычный долгоживущий диалог |
| **Команда / Team** | Оркестратор + независимые специалисты |
| **Специалист / Specialist** | настраиваемый исполнитель внутри команды; прежний Agent |
| **Оркестратор / Orchestrator** | управляющий специалист команды |
| **Проект / Project** | зарезервировано для будущего рабочего пространства с несколькими чатами, общей базой знаний, файлами и возможной общей памятью |
| **Агент / Agent** | зарезервировано для будущего автономного исполнителя с инструментами, правами и действиями во внешнем мире |

## Правило для кода

Активный доменный слой команды использует `Team*` и `Specialist*`.

Имена `Project*` и `Agent*` не добавляются для текущих команд и специалистов. Они допустимы только в явно обозначенном legacy-коде совместимости, который читает старые пользовательские данные или старый протокол.

## Legacy-совместимость

Старые версии Umnik сохраняли текущие команды и специалистов как `projects` и `agents`.

Миграционный слой поддерживает:

- каталоги `projects` → `teams`;
- каталоги `agents` → `specialists`;
- JSON-поля `projectId` → `teamId`;
- JSON-поля `agentId` → `specialistId`;
- владельцев базы знаний `PROJECT` / `AGENT` → `TEAM` / `SPECIALIST`;
- старые ключи настроек базы знаний;
- абсолютные пути к файлам внутри старого каталога `agents`;
- legacy-команду Оркестратора `CALL_AGENT` при чтении старого протокола.

Новые записи используют только новую терминологию.
