# Приватность Umnik

Umnik задуман как локальный Android-клиент для работы с OpenRouter. В приложении нет собственного серверного аккаунта Umnik и нет встроенного API-ключа автора.

## API-ключ

Пользователь вводит собственный API-ключ OpenRouter.

Ключ:

- хранится в приватном хранилище приложения;
- шифруется AES/GCM;
- ключ шифрования хранится через Android Keystore;
- не записывается в репозиторий;
- не отправляется автору Umnik;
- не должен попадать в диагностические логи.

## Что хранится локально

В локальном хранилище приложения могут находиться:

- история чатов;
- настройки проектов и этапов работы;
- импортированные навыки;
- файлы проектов;
- временные файлы конкретных чатов;
- созданные моделью файлы;
- короткий пользовательский профиль, если он заполнен;
- настройки интерфейса и выбранных моделей;
- служебные записи фоновых Batch- и Video-задач;
- диагностический журнал, если пользователь явно включил его запись.

## Что отправляется наружу

Когда пользователь запускает запрос, Umnik отправляет необходимые данные в OpenRouter. В зависимости от функции это могут быть:

- текст текущего сообщения;
- часть истории диалога;
- системные инструкции;
- мастер-инструкция и этапы проекта;
- выбранные навыки;
- файлы проекта;
- постоянные файлы текущего чата;
- разовые изображения, аудио, видео или документы;
- текстовые материалы отдельных Batch-задач;
- параметры reasoning и web search;
- текст, переданный для Speech/TTS;
- аудио, переданное для Transcription/STT.

OpenRouter может направить запрос выбранному провайдеру модели. Обработка этих данных регулируется условиями OpenRouter и соответствующего провайдера модели.

## Микрофон и голосовые сообщения

Разрешение на микрофон используется только после явного запуска записи пользователем. Umnik не ведёт постоянную или скрытую фоновую запись.

Запись создаётся локально на устройстве и отправляется наружу только после действия пользователя, требующего обработки этой записи. При отмене запись не отправляется модели.

## Web search

Если пользователь вручную включает **Поиск в сети**, запрос может дополнительно обрабатываться механизмом веб-поиска OpenRouter и связанными с ним поставщиками поиска.

## Озвучивание

В Umnik есть два варианта озвучивания ответа:

- локальная Android Text-to-Speech, поведение и политика которой зависят от установленного на устройстве TTS-движка;
- OpenRouter Speech по кнопке `OR`: текст ответа отправляется в OpenRouter для генерации речи.

Временная `OR`-озвучка ответа не добавляет MP3 в историю чата и не сохраняет его в хранилище Umnik. Полученные аудиофрагменты используются для текущего воспроизведения во временном кэше и удаляются после остановки/завершения.

Отдельный режим **Озвучить** может создавать сохраняемый аудиофайл, когда пользователь явно запускает эту функцию.

## Диагностика и логи

Диагностика включается пользователем вручную. Журнал предназначен для поиска ошибок и может содержать технические события: выбранный режим, тип модели, сетевой этап, HTTP-статус, длительность, тип вложения, возврат результата и stack trace ошибки.

Диагностика не должна записывать:

- API-ключ OpenRouter;
- содержимое личных сообщений;
- содержимое пользовательских файлов.

Перед передачей журнала другому человеку пользователь может просмотреть сохранённый файл самостоятельно.

## Телеметрия

На текущем этапе Umnik не содержит отдельного SDK аналитики, рекламного SDK или собственной серверной телеметрии автора приложения.

При добавлении функций, меняющих обработку данных, этот документ должен быть обновлён до публикации соответствующего релиза.
