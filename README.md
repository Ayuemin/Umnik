## Что есть в приложении

Umnik использует личный API-ключ OpenRouter. Встроенной подписки на модели нет: запросы оплачиваются по тарифам выбранных моделей.

Основные возможности:

- обычные чаты с выбором модели, файлами, изображениями, аудио, reasoning и веб-поиском там, где это поддерживает модель;
- быстрый выбор часто используемых моделей;
- память длинных чатов с режимами полного и гибридного контекста;
- навыки для обычных чатов;
- локальные базы знаний с поиском по Embeddings;
- проекты в виде кабинетов с независимыми ИИ-агентами;
- отдельные модели, инструкции, навыки, файлы, память и базы знаний у каждого агента;
- Оркестратор проекта, который может раздавать поручения агентам, запускать независимые задачи параллельно и передавать результаты между следующими шагами;
- предпусковая диагностика агентного проекта;
- генерация изображений, речь, распознавание, Batch, видео и Shell через поддерживаемые функции OpenRouter;
- фоновое выполнение пользовательских запросов: UIDT на Android 14+ и совместимый foreground-механизм на более старых версиях;
- безопасное восстановление прерванных запросов без скрытого повторного оплачиваемого POST;
- локальное хранилище, экспорт и диагностический журнал.

## Установка

1. Скачайте APK из [Releases](https://github.com/Ayuemin/Umnik/releases/latest).
2. Установите приложение на Android 8.0 или новее.
3. Откройте **Настройки → Подключение → OpenRouter**.
4. Добавьте свой API-ключ и проверьте подключение.
5. Выберите модель в разделе **Модели**.
6. Откройте обычный чат или создайте проект.

Официальные релизы подписываются постоянным ключом проекта. В Assets публикуются APK, SHA-256 APK и отпечаток сертификата подписи.

## Обычные чаты

Обычный чат хранит собственную переписку и может иметь:

- постоянную роль и инструкцию;
- файлы;
- навыки;
- индивидуальный режим контекста;
- собственную базу знаний.

Параллельные запросы можно выполнять в разных чатах. В одном и том же чате одновременно выполняется не более одного верхнеуровневого запроса.

## Проекты и агенты

В версии 1.19 проект — это кабинет для Оркестратора и агентов.

У проекта нет общей инструкции, навыков или базы знаний, которые автоматически наследуются всеми участниками. Каждый агент имеет собственную рабочую среду:

- роль и личную инструкцию;
- основную и быстрые модели;
- настройки контекста и памяти;
- reasoning и веб-поиск;
- навыки;
- постоянные файлы;
- базу знаний;
- отдельную историю разговора.

Имена специалистов произвольны и не задают специального поведения. Система различает агентов по внутренним идентификаторам, а Оркестратор использует их роли, инструкции и текущую задачу.

Оркестратор может запускать независимых специалистов параллельно. Зависимый шаг начинается после получения нужных предыдущих результатов. Успешно завершённые результаты сохраняются отдельно и не должны автоматически пересчитываться из-за ошибки другого агента.

Перед первым запуском проекта и после изменения его конфигурации выполняется локальная предпусковая диагностика критичных настроек.

Подробнее: [docs/PROJECTS.md](docs/PROJECTS.md) и [docs/ORCHESTRATOR.md](docs/ORCHESTRATOR.md).

## Фоновая работа

На Android 14+ запросы, явно запущенные пользователем, выполняются через системный механизм User-Initiated Data Transfer (UIDT) и JobScheduler. На более старых версиях Android используется foreground-механизм.

Android и прошивка производителя всё равно могут остановить работу. При неопределённом обрыве прямого OpenRouter-запроса Umnik не выполняет скрытый повтор оплачиваемого POST. Если OpenRouter позволяет безопасно прочитать уже существующий результат, приложение использует этот путь; иначе решение о повторном запросе остаётся пользователю.

## Данные и приватность

Чаты, настройки, агенты, навыки, локальные файлы и индексы баз знаний хранятся на устройстве.

API-ключ OpenRouter хранится локально с использованием Android Keystore. При работе с OpenRouter необходимые данные отправляются OpenRouter и выбранному им провайдеру модели.

Индексация базы знаний использует OpenRouter Embeddings, поэтому текст индексируемых фрагментов передаётся в OpenRouter.

Подробнее: [PRIVACY.md](PRIVACY.md).

## Сборка

Проект использует Kotlin, Jetpack Compose и Material 3. Минимальная версия Android — API 26.

CI выполняет Android Lint, unit-тесты, debug-сборку и неподписанную release-сборку через GitHub Actions. Неподписанная release-сборка проверяет тот же сценарий, который нужен внешним сборочным системам вроде F-Droid.

Без переменных `UMNIK_KEYSTORE_*` команда `./gradlew :app:assembleRelease` создаёт неподписанный release APK. Официальные GitHub Releases собираются и подписываются отдельным release workflow постоянным ключом проекта.
