## Что такое Umnik

Umnik — Android-приложение для работы с моделями через **OpenRouter**.

Приложение не привязывает пользователя к одной модели или одному готовому ИИ-сервису. Можно выбирать модели OpenRouter для обычных чатов и отдельных специалистов, подключать собственные инструкции, файлы, навыки и базы знаний, а для сложных задач использовать локальные инструменты Browser и Shell.

Umnik работает без собственного серверного бэкенда проекта: пользователь подключает свой API-ключ OpenRouter, а локальные данные приложения хранятся на устройстве.

## Основные возможности

### Обычные чаты

Каждый чат — самостоятельный долгоживущий диалог со своими настройками.

Можно использовать:

- собственную основную модель;
- инструкции и роль;
- reasoning и веб-поиск там, где их поддерживает выбранная модель;
- файлы и изображения;
- навыки;
- память и режимы контекста;
- отдельную базу знаний;
- инструменты OpenRouter и локальные инструменты Umnik.

Настройки одного чата не должны автоматически переноситься в другой.

### Команды и специалисты

**Команда** в Umnik — это **Оркестратор + независимые ИИ-специалисты**.

Каждый специалист имеет собственную рабочую среду:

- имя и роль;
- личную инструкцию;
- основную и дополнительные модели;
- reasoning и веб-поиск;
- навыки;
- постоянные файлы;
- базу знаний;
- память и отдельную историю разговора.

Оркестратор получает задачу пользователя, раздаёт поручения подходящим специалистам, может запускать независимые шаги параллельно и передавать результаты между зависимыми этапами.

Успешно завершённая работа одного специалиста сохраняется отдельно и не должна автоматически выполняться заново из-за ошибки другого.

> [!NOTE]
> В актуальной терминологии Umnik используются **Команды** и **Специалисты**. Названия **Проект** и **Агент** зарезервированы для будущих отдельных сущностей и не обозначают нынешние команды и специалистов.

Подробнее: [Команды](docs/TEAMS.md) · [Оркестратор](docs/ORCHESTRATOR.md) · [Терминология](docs/DOMAIN_TERMINOLOGY.md)

### База знаний

База знаний предназначена для больших документов, которые не нужно целиком отправлять основной модели при каждом вопросе.

Umnik умеет:

- извлекать текст из поддерживаемых документов;
- строить смысловой индекс через OpenRouter Embeddings;
- хранить индекс локально;
- искать подходящие фрагменты по запросу;
- передавать основной модели только релевантные части;
- предоставлять совместимым моделям локальный инструмент `knowledge_search` для самостоятельного поиска.

База знаний может принадлежать обычному чату или конкретному специалисту команды. База одного специалиста не становится автоматически доступна другим.

Поддерживаются, в частности, PDF с текстовым слоем, EPUB, FB2, DOCX, TXT, Markdown, HTML/XML, JSON/CSV/YAML и текстовые файлы кода.

Подробнее: [Базы знаний](docs/KNOWLEDGE_BASE.md)

### Local Browser

Local Browser позволяет модели работать с публичными веб-страницами не только через обычную поисковую выдачу, но и как с реальной браузерной сессией.

Он умеет:

- открывать страницы;
- читать содержимое;
- переходить по ссылкам;
- прокручивать страницу;
- заполнять доступные поля;
- скачивать файлы;
- сохранять состояние сессии;
- передавать скачанные файлы в чат и Local Shell.

Для долгих действий Browser показывает ход выполнения и при необходимости может передать управление пользователю.

### Local Shell

Local Shell — локальная рабочая среда для задач с файлами и кодом.

Он умеет:

- читать, искать, создавать и изменять файлы;
- запускать ограниченные локальные команды;
- использовать встроенный Python;
- распаковывать и создавать архивы;
- скачивать публичные файлы;
- экспортировать готовый результат обратно в чат;
- работать с Git через отдельный безопасный инструмент.

Поддерживаемые Git-действия включают публичный clone, init, status, diff, add, commit, log и другие штатные операции, предусмотренные Local Shell.

Служебный каталог `.git` защищён от ручной подмены через обычную запись или Python: менять Git metadata разрешено только штатному Git-инструменту Shell. При экспорте проекта `.git` не попадает в пользовательский ZIP.

Для длинных задач есть защита от повторяющихся безрезультатных циклов, структурных ошибок, сетевых зависаний и бессмысленного повторного запуска после терминального сбоя.

### Инструменты OpenRouter

В зависимости от возможностей выбранной модели и режима Umnik также поддерживает инструменты OpenRouter, включая:

- генерацию изображений;
- распознавание речи;
- озвучивание;
- Batch;
- видео;
- reasoning;
- веб-поиск.

Доступность конкретной функции зависит от модели и OpenRouter.

### «Об ответе» и диагностика

Для ответа можно посмотреть техническую информацию, в том числе:

- фактически использованную модель и провайдера;
- входные и выходные токены;
- известную стоимость запроса;
- использование контекста;
- ход выполнения инструментов;
- диагностические сведения о запросе.

Стоимость дочерних модельных вызовов Local Shell входит в общий учёт запроса, когда OpenRouter возвращает данные о стоимости.

Для поиска сложных ошибок в приложении есть диагностический журнал с сетевыми фазами и событиями инструментов без намеренного вывода секретов API-ключа.

## Установка

Umnik требует **Android 8.0 (API 26) или новее**.

### Рекомендуемый вариант — Pre-release

1. Откройте [GitHub Releases](https://github.com/Ayuemin/Umnik/releases).
2. Найдите **самый новый релиз с пометкой Pre-release**.
3. Скачайте APK из `Assets`.
4. Установите APK на устройство.
5. Добавьте свой API-ключ OpenRouter в настройках приложения.
6. Выберите модели и начните новый чат или создайте команду.

Pre-release — рекомендуемый вариант для текущего Umnik: именно в нём находятся самые свежие возможности и исправления.

### Стабильный релиз

[Последний стабильный релиз](https://github.com/Ayuemin/Umnik/releases/latest) обновляется осторожнее и может заметно отставать от текущей тестовой ветки по функциям.

Официальные GitHub APK подписываются постоянным ключом проекта. Для релизов публикуются APK, SHA-256 APK и отпечаток сертификата подписи.

## OpenRouter и расходы

Umnik не продаёт собственную подписку на модели.

Для работы нужен личный **OpenRouter API key**. Стоимость запросов определяется выбранной моделью, провайдером и тарифами OpenRouter.

Некоторые сложные действия могут включать несколько модельных вызовов: например, основной ответ, Local Shell, Оркестратор или несколько специалистов команды. Поэтому итоговая стоимость задачи может быть выше стоимости одного одиночного ответа модели.

## Данные и приватность

Основные пользовательские данные Umnik хранятся локально на Android-устройстве, включая чаты, настройки специалистов, навыки, локальные файлы и индексы базы знаний.

API-ключ OpenRouter хранится с использованием Android Keystore.

При обращении к моделям необходимые данные отправляются OpenRouter и выбранному им провайдеру. При индексации базы знаний текстовые фрагменты отправляются в OpenRouter Embeddings для построения векторов; сами локальные индексы остаются на устройстве.

Подробнее: [PRIVACY.md](PRIVACY.md)

## Фоновая работа

Пользовательские запросы могут продолжать выполняться в фоне.

На Android 14+ Umnik использует системный механизм User-Initiated Data Transfer и JobScheduler для подходящих пользовательских операций; на более старых версиях Android используется совместимый foreground-механизм.

Android или прошивка производителя всё равно могут остановить процесс. При неопределённом сетевом обрыве Umnik старается не выполнять скрытый повтор потенциально платного запроса без достаточных оснований.

## Технологии

- Kotlin
- Jetpack Compose
- Material 3
- OpenRouter API
- OkHttp
- локальное Android-хранилище
- Android Keystore
- JGit для Git-операций Local Shell
- встроенный Python runtime для Local Shell

Минимальная версия Android: **API 26**.

## Сборка

Обычный CI проверяет Android Lint, unit-тесты, debug-сборку и release-сборку.

Release-сборки используют R8 shrinking/optimization. Подписанные GitHub Releases и Pre-releases собираются отдельными workflow с постоянным ключом проекта и дополнительной проверкой сертификата подписи.

Без release signing variables локальная команда `./gradlew :app:assembleRelease` создаёт неподписанную release-сборку.

Подробнее для разработчиков: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) · [CONTRIBUTING.md](CONTRIBUTING.md)
