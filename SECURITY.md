# Security Policy

## Поддерживаемые версии

Umnik находится в активной разработке. Исправления безопасности в первую очередь выпускаются для последней стабильной версии.

## API-ключи и секреты

Никогда не публикуйте в Issues, Discussions, pull request или скриншотах:

- OpenRouter API key;
- Android signing keystore;
- пароли signing key;
- другие токены и приватные данные.

Если секрет случайно опубликован, его нужно считать скомпрометированным и немедленно отозвать/заменить у соответствующего провайдера.

## Сообщение об уязвимости

Для реальной уязвимости не публикуйте рабочий exploit или чувствительные детали в обычном issue. Используйте приватный канал GitHub Security / Report a vulnerability, если он доступен для репозитория.

Если приватный security report недоступен, создайте минимальный issue без секретов и эксплуатационных деталей с просьбой открыть приватный канал связи.

## Модель угроз

Umnik работает с чувствительными данными пользователя: API-ключом, историей чатов и файлами. Изменения, затрагивающие хранение секретов, доступ к файлам, сетевые запросы, WebView, intents, FileProvider или выполнение локального кода, требуют особенно внимательного review.

Проект намеренно не исполняет произвольные скрипты из импортированных навыков.
