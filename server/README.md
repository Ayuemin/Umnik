# Umnik Personal Server

Личная серверная часть Umnik для одного владельца. Это не многопользовательский сервис.

## Зачем нужен сервер

В прямом режиме Umnik обращается к OpenRouter с телефона. На Android 14+ приложение использует User-Initiated Data Transfer job, но Android и прошивка производителя всё равно могут остановить фоновую работу.

В серверном режиме телефон создаёт задачу на своём VPS и затем читает её состояние. Запрос к OpenRouter выполняется на VPS и не зависит от жизненного цикла Android-приложения.

Сервер не повторяет автоматически оплачиваемый `POST` к OpenRouter после неопределённой сетевой ошибки. Это снижает риск двойной оплаты.

## Протокол v1

- `GET /health` — проверка доступности;
- `GET /v1/capabilities` — возможности протокола, Bearer-токен обязателен;
- `POST /v1/chat/jobs` — создать текстовую задачу;
- `GET /v1/chat/jobs/{id}` — получить состояние или готовый ответ.

`client_request_id` идемпотентен. Повтор с тем же ID и тем же payload возвращает уже существующую задачу. Тот же ID с другим payload получает `409`.

## Установка на VPS

Текущий автоматический инсталлятор рассчитан на свежий Debian/Ubuntu VPS с публичным IPv4 и свободными входящими портами 80 и 443. Он устанавливает Docker, Nginx и HTTPS-сертификат Let’s Encrypt, поэтому его не следует запускать вслепую на сервере, где уже работает свой Nginx/Caddy или сайты.

Перед запуском задайте ключ OpenRouter:

```bash
export OPENROUTER_API_KEY='sk-or-...'
sudo -E bash server/install.sh
```

Локальный порт контейнера по умолчанию `8787`. Если он занят другим сервисом, можно выбрать другой:

```bash
export UMNIK_LOCAL_PORT=8877
sudo -E bash server/install.sh
```

Если репозиторий ещё не скачан, сначала получите текущую версию Umnik или передайте `UMNIK_GIT_REF` при автоматизации установки. По умолчанию инсталлятор использует ветку `main`.

После успешной установки он выводит:

- HTTPS-адрес сервера;
- личный токен сервера;
- выбранный локальный порт backend.

В Android-приложении откройте **Настройки → OpenRouter**, сохраните адрес и токен, проверьте соединение и выберите **Через сервер**. Адрес может содержать нестандартный HTTPS-порт, например `https://server.example:8443`.

## Локальный запуск для разработки

Создайте `server/.env`:

```env
OPENROUTER_API_KEY=sk-or-...
UMNIK_SERVER_TOKEN=случайная-длинная-строка
UMNIK_LOCAL_PORT=8787
```

Затем:

```bash
cd server
docker compose up -d --build
```

Compose публикует приложение только на `127.0.0.1:${UMNIK_LOCAL_PORT}`. Для внешнего доступа используйте HTTPS reverse proxy. Не открывайте этот внутренний backend-порт напрямую в интернет.

Если VPS уже используется другими сервисами, безопаснее вручную добавить Umnik в существующий reverse proxy и выбрать свободный локальный порт, чем запускать текущий автоматический инсталлятор.

## Хранение и восстановление

Состояние задач хранится в SQLite volume `umnik-data`. Телефон сохраняет данные восстановления до сетевого запроса. После потери процесса или остановки UIDT он может снова обратиться к тому же серверному job и получить результат.

Если сам VPS перезапустился во время незавершённого запроса, такая задача помечается `failed`. Сервер сознательно не повторяет запрос к OpenRouter вслепую, потому что провайдер мог уже принять первый POST.

Ручная кнопка **Стоп** в Umnik удаляет локальное восстановление, поэтому завершившийся позже серверный job не должен сам появиться в чате.

## Ограничения текущего протокола

Через сервер сейчас направляется обычный текстовый чат. Изображения, аудио, video, batch и другие специальные endpoints пока выполняются напрямую. Потоковые частичные ответы через VPS пока не реализованы: клиент получает итоговый результат после завершения job.

Автоматическое развёртывание VPS по SSH непосредственно из приложения остаётся отдельным следующим этапом. Для него будут нужны настраиваемые SSH-хост и порт (по умолчанию 22), чтобы поддерживать серверы с нестандартной SSH-конфигурацией. Текущий сервер уже рассчитан так, чтобы позже добавить такой установщик без изменения Android-протокола.
