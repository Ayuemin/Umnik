# Contributing to Umnik

Спасибо за интерес к проекту.

## Перед изменением кода

Для заметной новой функции лучше сначала создать Issue и коротко описать:

- проблему пользователя;
- предполагаемое поведение;
- почему существующего решения недостаточно.

Для небольших исправлений можно сразу открыть pull request.

## Сборка

Нужно:

- JDK 17;
- Android SDK 36;
- Gradle 8.13.

Проверочная сборка:

```bash
gradle :app:assembleDebug
```

GitHub Actions выполняет ту же базовую проверку для push и pull request.

## Принципы UI

Umnik ориентирован на компактный взрослый интерфейс:

- Material 3;
- понятные Material icons вместо декоративных emoji;
- минимум постоянно видимых кнопок;
- функции модели становятся недоступными, если модель их не поддерживает, но не включаются автоматически;
- максимум пространства отдаётся самому чату.

## Безопасность

Не добавляйте API-ключи, keystore, пароли или токены в код, тестовые данные, workflow или screenshots.

Не добавляйте автоматическое выполнение скриптов из импортированных навыков без отдельного security design review.

## Лицензирование вкладов

Отправляя код, документацию или другие материалы в Umnik через pull request или иной вклад в репозиторий, вы соглашаетесь предоставить этот вклад на условиях **GNU GPL v3.0 or later** (`GPL-3.0-or-later`), если для конкретного файла явно не указано иное.

## Pull request

Хороший PR должен:

- решать одну понятную задачу;
- объяснять пользовательский эффект;
- собираться в Android CI;
- не менять applicationId без отдельного обсуждения;
- обновлять `CHANGELOG.md`, если изменение заметно пользователю.
