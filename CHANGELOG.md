# История изменений

Все заметные пользовательские изменения Umnik фиксируются здесь. Формат ориентирован на Keep a Changelog, версии следуют Semantic Versioning настолько, насколько это возможно на стадии beta.

## Unreleased

## v0.7.4 - 2026-09-11

- Значки действий под сообщениями уменьшены и приведены к более компактному стилю нового интерфейса.
- Markdown-таблицы теперь распознаются и отображаются как прокручиваемые таблицы вместо строк с символами `|`.
- Для глобальных навыков уточнены состояния: «Подключить к каждому чату» и «Подключён к каждому чату».
- В поле ввода появились компактные индикаторы активных навыков, размышления и поиска в сети.
- Настройка звука ответа расширена: основной сигнал остаётся доступен всегда, добавлены ещё варианты и регулировка громкости.

## v0.7.3 - 2026-09-10

- Добавлен полноценный рендеринг Markdown в ответах модели: заголовки, жирный и курсивный текст, зачёркивание, inline-код, списки, цитаты, разделители и ссылки.
- Кодовые блоки и специальные блоки для копирования по-прежнему отображаются отдельными карточками.
- В «Хранилище Umnik» служебные файлы проектов, чатов и навыков отделены от обычных удаляемых файлов и убраны в отдельный сворачиваемый раздел.
- Добавлен выбор одного или нескольких рабочих файлов с последующим групповым удалением; кнопка сохранения копии оставлена у каждого файла.
- В списке навыков активное состояние теперь отмечается галочкой.
- Добавлено пояснение прямо в приложении: подключённый навык автоматически добавляет свои инструкции и текстовые материалы к каждому текстовому запросу и сам ничего не запускает.
- В настройках проекта активные навыки также отмечаются галочкой и снабжены кратким пояснением о влиянии на запросы проекта.
- Добавлена цветовая схема «Свой цвет» с выбором пользовательского акцентного оттенка.

## v0.7.2 - 2026-09-10

- В панели `+` действие «Изображение» переименовано в «Создать».
- Нижняя навигация в настройках и навыках удалена; возврат в чат выполняется закреплённой стрелкой «Назад».
- Настройки перестроены по частоте использования: модели и размышления выше, профиль и цветовая схема ниже, API-ключ в самом низу.
- API-ключ и «Коротко обо мне» стали сворачиваемыми блоками.
- Сила размышления настраивается отдельно для каждой модели из быстрого списка; поддерживаемые уровни визуально выделяются, неподдерживаемые затемняются.
- При смене модели Umnik автоматически использует сохранённый для неё уровень reasoning.
- Для модели генерации изображений в настройках показываются её reasoning-возможности, если OpenRouter сообщает о них.
- Проекты, история чатов, настройки чата/проекта, выбор моделей, быстрые модели и хранилище открываются на весь экран с неподвижной кнопкой «Назад».

## v0.7.1 - 2026-09-10

- Кнопка Stop мягко пульсирует примерно раз в секунду во время активного запроса, показывая, что модель продолжает работать.
- Полностью переработан главный экран чата в компактном стиле.
- Быстрый выбор модели перенесён в верхнюю левую часть экрана.
- Новый чат доступен отдельной кнопкой сверху.
- Проекты, история чатов, навыки и настройки собраны в единое меню.
- Нижняя панель навигации скрыта на главном экране.
- Скрепка, камера, режим изображений, web search и reasoning перенесены в панель по кнопке `+`.
- Поле ввода стало единым компактным блоком с динамической кнопкой Send/Stop.

## v0.7.0 - 2026-09-09

### Changed

- Введена постоянная release-подпись приложения для публичных GitHub Releases.
- Публичная сборка теперь использует отдельный release keystore вместо временной debug-подписи.
- Release workflow проверяет наличие signing secrets до сборки.
- Для релизного APK публикуется SHA-256 checksum.
- Репозиторий подготовлен к нормальным обновлениям приложения поверх установленной версии, начиная с этой ветки подписи.

### Important

- v0.7.0 является базовой версией новой постоянной подписи.
- Старые preview-сборки v0.6.x были подписаны тестовым ключом. Android может потребовать удалить установленную v0.6.x перед установкой v0.7.0.
- После установки v0.7.0 следующие релизы, подписанные тем же ключом, должны обновляться поверх неё без переустановки.

## v0.6.7 - 2026-09-09

### Fixed

- Постоянные файлы чата теперь отображаются в пользовательском сообщении, с которым реально отправляются модели.
- Добавлена проверка отсутствующей локальной копии файла до запуска запроса.
- Убрано лишнее Base64-кодирование текстовых вложений перед их отправкой как текста.
- Повторный запрос разрешён для сообщений, чьи постоянные файлы всё ещё присутствуют в контексте чата.

## v0.6.6 - 2026-09-08

### Added

- Остановка активной генерации прямо кнопкой отправки: стрелка меняется на квадрат Stop.
- Отмена активного HTTP-запроса к OpenRouter.

### Changed

- Убран отдельный индикатор работы модели.
- Поле ввода сделано компактнее, placeholder удалён.

## v0.6.5 - 2026-09-08

### Added

- Временные постоянные файлы конкретного чата.
- Текстовые документы и PDF автоматически остаются доступными следующим моделям в том же диалоге.
- Автоматическое удаление файлов при очистке или удалении чата.

## v0.6.4 - 2026-09-08

### Added

- Быстрая смена текстовой модели внутри текущего чата.
- Набор быстрых моделей в настройках.
- Отдельная модель запоминается для каждого чата.

## v0.6.3 - 2026-09-08

### Added

- Учёт input modalities выбранной модели.
- Проверка поддержки изображений, аудио и видео до отправки.
- Корректная мультимодальная упаковка image, audio, video, PDF и текстовых файлов.
- Доступность reasoning зависит от возможностей модели.

## v0.6.2 - 2026-09-08

### Added

- Съёмка фото прямо из чата.
- Копирование собственных сообщений.
- «Спросить ещё раз» для текстовых сообщений.
- Опциональный короткий профиль пользователя: выключен, только проекты или везде.

## v0.1.0

### Added

- Первый Android-клиент Umnik.
- OpenRouter chat и выбор модели.
- Локальные навыки из `SKILL.md` и папок.
- Файловые вложения.
- Tool calling и локальный инструмент `create_file`.
- Сохранение созданных файлов через Android SAF.
- Шифрование API-ключа через Android Keystore.

> Между v0.1.0 и v0.6.2 были промежуточные внутренние итерации активной разработки. Их отдельные changelog-записи не восстанавливались задним числом, чтобы не придумывать неточные детали.
